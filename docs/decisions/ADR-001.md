# ADR-001 — Fundação técnica e limites das integrações

- **Data:** 23/10/2026
- **Status:** adotada exclusivamente para a implementação delimitada da HUB-02; não substitui aprovação final da auditoria.
- **Escopo:** repositório `emagrecacomlevia-svg/crm-levia` (ID `1431576812`).

## Contexto

Projeto novo já criado e conectado ao Lovable. A aplicação inicial é um template TanStack Start; não representa CRM funcional. GitHub é a fonte de código versionado. O repositório é público. O projeto Lovable deve permanecer sincronizável, sem chamadas de geração ou deploy.

## Decisões

1. Preservar React/TypeScript/TanStack Start/Router/Vite/Tailwind/Bun e o lockfile existente, sem criar outro roteador.
2. Implementar somente home institucional demonstrativa e módulos tipados estáticos, preservando root, server, QueryClient e setup Lovable.
3. Trabalhar exclusivamente em `feature/hub-02-foundation`, com commits novos e PR Draft, **sem merge ou alteração da main**.
4. Usar GitHub Actions apenas para verificações de qualidade, sob permissões de leitura.
5. Não conectar nem criar Supabase. Ambiente administrativo independente, RLS, Auth e políticas serão decididos e implementados posteriormente.
6. Não criar CRM próprio, editor, sincronização Drive, publicação automática, autenticação fictícia ou dados reais nesta fase.

## Alternativas não adotadas

- Substituir TanStack Start por roteador distinto: elevaria risco e prejudicaria a integração atual, sem evidência de necessidade.
- Introduzir npm/pnpm e novos lockfiles: risco de instalação não reproduzível.
- Implementar banco/auth já na fundação: fora de autorização.

## Consequências e condições futuras

A aplicação demonstra direção visual e organização de código, mas não é sistema pronto para uso. Build e testes são pré-requisitos técnicos, não aprovação de negócio. Mudanças na integração Lovable, arquitetura de rotas, banco, serviços ou publicação exigem decisão expressa.
